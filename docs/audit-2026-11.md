# Code audit, November 2026

A whole-repo audit run with the ponytail-audit skill (`.claude/skills/ponytail-audit`), which
reports only findings with a concrete failing case. Assumed load: a small team on one
workstation's GPU.

**Verdict:** healthy. Sign-in, sessions, CSRF, sign-in throttling, the OpenFGA freshness guard,
the job queue and the parser sandbox were all sound.

## Findings and status

| # | Finding | Where | Status |
|---|---|---|---|
| 1 | Two uploads of the same name shared one temporary file, so the second could overwrite the first, then crash, leaving a record that doesn't match its file | `api/library_routes.py`, upload | **Fixed:** each upload gets its own temp file; it takes the real name with a hard link, which fails if the name is taken (409). Test added |
| 2 | Nothing limited how many questions one user ran at once; one script or retrying tab could hold the GPU for everyone | `api/chat_routes.py`, `/api/ask` | **Fixed:** one running question per user (`MAX_CONCURRENT_ASKS`), more get a 429. In-process count, fine for the single API process `run.sh` starts. Test added |
| 3 | The claim check under-rated correct Hindi answers (a right "90 days" answer scored 0.17) | `grounding.py` | **Fixed:** the judge compares meaning across languages; Hindi faithfulness 0.667 → 0.875. Test added |
| 4 | Source YAML files re-read on every request; a scoped question loads all ~1,500 folder rows | `sources.py` | Open (nice to have; milliseconds today) |

Found and fixed during the audit, in the then-new claim check: the judge saw more of each
passage than the answer model (2,500 vs 1,800 characters), and passages weren't datamarked, so
a document could try to steer the judge. Both now reuse the answer model's rules.

**Not checked:** the prompt gate internals (`gate.py`), the CLI, chunking, the admin pages of the
web interface, and behaviour under real concurrent load.
